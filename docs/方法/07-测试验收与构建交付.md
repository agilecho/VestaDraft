# 测试验收与构建交付

验收要证明用户获得了正确、可继续编辑的结果。源码、客户端 bundle、锁定软件制品与实际 runtime 的身份应对应，证据必须来自本次真实链。

## 1. 按证明范围组织检查

| 层次 | 证明什么 | 不能顺带证明什么 |
|---|---|---|
| 新增逻辑单测 | 本次命令、适配、守卫、错误与状态转换 | 实际页面与生产服务已接通 |
| 本款原生/页面契约 | 真接口、字段、返回、文件格式和渲染 | 平台身份、空间和工具运输 |
| 零模型跨组件 | 正式工具→页面/CLI→真实文件的往返 | 模型会正确选择并使用工具 |
| 授权真实模型任务 | 工具发现、使用、自纠与用户结果 | 所有领域功能和所有异常都成立 |
| 关页重开与回归 | 持久化和受影响旧能力可继续使用 | 未覆盖环境与功能的完整性 |

施工期间按 D3-16 和现行节奏运行新增、直接关联测试及关键往返；完整回归仍归既定最终关口，不删除，也不因方法文档重复提前执行。

## 2. 实时 Agent 软件的验收样本

固定一条包含精确内容的任务。调用真实软件工具，在用户正在看的页面中产生修改；独立检查领域结构和画面。用户手改后，再让工具读取并继续操作，证明双方共享同一状态。

随后验证保存真实写入，导出内容正确，销毁页面重开后相同内容存在，再继续修改。对页面持有编辑权与无页面路径的交接分别核真实文件。测试框架不得自己写出最终工程来替代软件保存。

## 3. 按领域选择独立预期

| 领域 | 内容与结构 | 画面/输出 |
|---|---|---|
| 文档 | 指定文字、段落、表格、样式、图片关系 | 中文字形、分页和导出 |
| 表格 | 公式、依赖结果、范围与类型 | 格式、图表与重开值 |
| 图形/CAD | 对象、坐标、单位、几何约束 | 视口和 SVG/位图/工程读回 |
| 音频/视频 | 采样/帧率、轨道、时长、关键帧 | 音频信号、指定帧与成片 |
| 三维/材质 | 网格、变换、UV、节点和资源 | 渲染与导出资产 |

相似度可作为辅助指标，不能替代核心计算和交互结果。生成程序的自测报告要注明来源；关键结论用外部输入、内容读取或独立测量确认。

## 4. 质量驱动自身也要可信

断言失败应以失败退出，跳过有原因，超时不能留假 running；受控错误输入能触发预期拒绝。异常证据与正常对照一起保留，明确哪些是真运行、哪些是替身。

每轮使用新证据目录，记录实际源码、镜像、软件制品、输入和加载指纹。旧日志、截图和 result 原件保持不变；审计只读，不能为了修汇总覆盖旧证据。当前卡累计费用与本次 attempt 费用分别读取，不因换会话重置。

## 5. 锁定可交付输入

参考现有 `craft/<software>/upstream.lock.json` 与构建脚本，锁定源码、Cargo/npm 等依赖、补丁、工具链、字体/i18n 输入和构建镜像。按目标环境产出 Web 与 CLI；Mac 可运行不能证明 Linux/x86 镜像可用。

Web 包身份包括实际 JS/WASM、压缩旁文件、字体和许可。补丁保留上游版本号时，宿主仍需区分不同字节的制品，避免缓存命中旧包。上线前核实际加载摘要，不能只看界面版本号。

## 6. 发布前核对的用户结果

- 初次进入有清楚的加载与失败反馈，重试不会复活旧任务。
- 中文 UI、内容字体和输入法在目标 Web 环境实际可用。
- Agent 能查询并操作当前作品，结果可见且可检查。
- 保存、导出、冲突、空间满与关闭重开有真实内容证据。
- 文件路径与嵌套资源受个人空间约束；管理员只读入口不能执行变更。
- 模型、网络和任务生命周期沿用平台治理；没有隐藏旁路。
- 必要回归及既定最终关口完成，未验证项如实登记。

上述是验收方向。每款具体命令、运行环境、性能门槛和证据清单由届时任务卡固定，不能把本文当作启动旧环境的命令清单。
