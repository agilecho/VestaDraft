# Craft 软件的目标与端到端路线

目标是交付一款有自身编辑能力的软件：人能在浏览器里操作，Agent 能通过命令操作同一份作品，结果实时可见，文件能保存和再次打开。WordCraft 提供了本项目中可复用的接入样本；下一款软件应沿用其方法，领域内核与文件协议按本款重新核实。

本文是通用方法建议，不是某款软件的实施授权。项目依据见 [平台接入指南](../接入/01-IntegrateCraft接入与复用边界.md) 和 [来源登记](../参考/依据与差异登记.md)。

## 1. 六个必须贯通的结果

| 结果 | 用户能做什么 | 证明方式 |
|---|---|---|
| 核心工作成立 | 完成一个有意义的文档、图形、音频或工程任务 | 预先固定的内容与领域断言 |
| Web 可用 | 打开、选择、编辑、撤销、缩放等核心交互正常 | 真实浏览器与目标设备检查 |
| Agent 可操作 | 查询参数、执行命令、检查结果、自行纠错 | 真实工具执行，新增接缝先零模型验证 |
| 实时可见 | Agent 改的是当前页面持有的作品 | 工具前后页面内容、修订与画面对照 |
| 作品可持续 | 保存、另存、导出、关页重开后继续修改 | 真实文件内容与新页面读回 |
| 平台能治理 | 用户空间、模型计费、权限、停止均生效 | 服务端与存储边界验证 |

“网页能加载”“MCP 调用成功”“图片看起来相似”分别只覆盖其中一部分。软件完成度按完整用户结果登记。

## 2. 先确定 Craft 的对象

三类工作要分别评估：

1. 已有开源软件具备核心能力：优先复用现有领域引擎、命令和文件格式，补 Web 或平台接缝。
2. 目标软件用于行为参考、需要另建实现：先研究用户任务、领域规则和格式，再原创实现核心闭环；记录来源与未知项。
3. 只需给已有软件添加 Agent 控制：确认正式命令接口和 Web 形态，完成薄适配，避免另造完整编辑器。

决定属于哪类后再选技术栈。Tauri、egui、React、WASM 都是可选实现，页面同一状态和文件可持续是交付要求。只有桌面壳或只有浏览器文件识别器的项目，需要单独评估到完整 Web 编辑器的距离。

## 3. 以一条完整用户链作为首个切片

例如做文档软件，首个切片可以是：“输入中文说明，Agent 在打开的编辑器里新建带标题、段落和表格的文稿，用户能看到变化，手改一处，保存成文件，再关页重开继续改。”

这个切片同时要求文档模型、编辑命令、页面入口、Agent 工具、渲染和文件桥。格式兼容范围可以缩小，完整链应保留。下一条切片再增加图片、页眉、复杂表格等能力。

每个切片都写明目标用户、输入、预期内容、可见变化、保存路径与格式、重开操作、关键失败与恢复方式。性能要求按用户任务测定，例如首次加载、命令执行与可见变化的时间，不用统一的任意数字代替本款实际门槛。

## 4. 推进阶段及交付物

| 阶段 | 工作 | 应交付的材料 | 进入下一阶段的依据 |
|---|---|---|---|
| 研究 | 固定版本，研究真实行为和接口 | 功能边界、输入样本、证据与缺口 | 核心链没有未解释的关键前提 |
| 领域闭环 | 实现或复用内核、命令和序列化 | 无界面可验证的领域操作 | 内容断言和新增逻辑单测成立 |
| 页面闭环 | 页面调用同一命令，完成渲染和导入导出 | 可操作 Web 软件、页面接口 | 人与程序操作同一状态 |
| Agent 闭环 | 正式工具调用到当前页面 | 工具说明、状态反馈、异常恢复 | 真实工具往返与画面同步成立 |
| 平台闭环 | 接工作台、个人空间、治理 | 锁定构建、宿主接缝与完整用户链证据 | 保存、导出、重开和边界成立 |
| 范围扩展 | 按下一条用户链扩充 | 新能力及必要回归 | 原有完整链保持可用 |

已有项目不必重做前几阶段，直接复用已经证明的成果。本项目实际施工顺序和关口以当前卡为准，本文不启动并行施工。

## 5. 每款软件都要留下的工程资料

- 产品范围：先支持哪类用户结果，格式与功能明确到可测试。
- 架构：核心状态在哪、谁可以改、命令怎样到达它、文件怎样写回。
- 接口：命令 schema、返回值、错误、批处理、取消、分页与大对象传输。
- 运行状态：已证明、部分可用、未验证与已知缺陷，逐项保留证据入口。
- 构建：源码、依赖、补丁、字体、工具链及实际制品身份。
- 验收：真实输入、独立预期、用户链、异常与恢复、重开结果。

用 [单款软件模板](../模板/单款软件Craft方案模板.md) 承接这些材料。发卡仍由现行角色承担，研究报告不自动转成开工卡。

## 6. 常见偏离及纠正

| 偏离 | 会发生什么 | 纠正方向 |
|---|---|---|
| 只复刻界面 | 能截图但无法持续编辑 | 先确定领域模型和操作结果 |
| 只做无头 MCP | Agent 改了另一份内存文档 | 当前页面持有编辑权时走页面接口 |
| 用脚本直接改工程 | 页面状态与文件分叉 | 修改通过本款正式命令；外改按冲突处理 |
| 最后才设计保存 | 已编辑却无法可靠交付 | 首个切片就接宿主确认和重开 |
| 只靠模型自报通过 | 生成了结论，结果缺乏证明 | 用独立内容、渲染和真实往返检查 |
| 第一轮追全部功能 | 每层都有半成品 | 按完整用户链逐条扩展 |
