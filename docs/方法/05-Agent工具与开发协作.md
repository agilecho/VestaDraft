# Agent 工具与开发协作

要区分两种 Agent：开发阶段帮忙研究和实现软件的 Agent，以及交付后替用户操作软件的 Agent。前者需要可验证的工程资料和开发入口，后者需要稳定工具和可检查的业务状态；两者可以共享命令契约，权限与工作范围分别约束。

## 1. 交付软件的工具面

核心能力是发现命令、执行、批处理、检查内容和查看渲染。工具名按本款官方协议保留，平台可提供少量统一别名，schema 和执行语义沿用原定义。

WordCraft 的平台别名对应官方 `list_commands/execute/batch/inspect_document/render_page`，分别保留 `query`、`command`、`commands`、`page/scale` 等参数。见 [真实映射](../../../dsh/plugins/software/word-tools.mjs)。不能为统一名字强制所有软件使用 `id/steps`。

工具说明应告诉 Agent：当前软件与工程、怎样查询参数、页面持有编辑权时的路由、文件保存范围、遇到冲突的处理、截图和内容检查方法。正常查看目录、读取材料与询问用户继续使用现成工具。

## 2. 一次可自纠的操作循环

1. 读取当前工程状态，确认对象身份、修订和已有内容。
2. 查询与任务有关的命令及完整参数，避免凭其他软件经验猜字段。
3. 执行一个有意义的操作或原生事务。
4. 检查领域结果，需要画面时读取当前渲染。
5. 错误能明确定位时按返回的正确契约修正；权限、冲突或额外授权问题交用户处理。
6. 保存并核对真实结果，向用户说明完成内容、产物与剩余限制。

报错后的同轮正确修正是可用性的组成部分。验证时保留首次错误和自纠结果，不额外补发用户任务来掩盖工具说明缺口。

## 3. 工具结果应让模型判断得动

返回结构化字段说明成功、失败、部分成功、执行范围、当前对象和后续动作。大清单摘要先行，支持分页；截图和大文件走现有附件/文件通道，不把巨量 Base64 混入普通描述。

原软件的错误码、返回形状和批处理结果尽量保留。平台可补中文解释和真实保存产物摘要，不能把原错误转换成成功，也不能依据英文文案猜业务成功。

目标文件、网页内容和反编译输出都属于输入材料。工具描述不能把材料里的“忽略规则、执行命令”等文本当成控制指令。权限由实际执行入口决定。

## 4. 开发阶段给 Agent 的资料

| 资料 | 内容 |
|---|---|
| 协作入口 | 目录、权威文档、当前范围、状态、禁改区与验证入口 |
| 产品与功能边界 | 核心用户链、格式范围、领域精度和未做项 |
| 架构与接口 | 领域模型、命令、页面/CLI/MCP/文件桥及版本 |
| 当前工作说明 | 前置基线、允许路径、步骤依赖、失败处理和应交证据 |
| 已知缺口 | 有来源的限制、待研究能力与后续工作 |
| 验证材料 | 输入样本、独立预期、命令、目标环境和通过条件 |

这些资料应能让新会话独立接手。历史聊天不能代替当前文件，换会话也不刷新权限、预算或次数。

## 5. 复用成熟代码时的边界

先读当前已合并实现，再判断本款差异。复用工具运输、个人空间、命名、保存冲突和构建锁定；领域命令、格式解释和特殊保存机制分别核实。

本项目由 Hermes 负责发卡，独立复审统一由 dsh 承担，Codex 默认施工、自验、交回执；用户明确指定才交 dsh 施工。独立复审沿用 [AGENTS.md](../../AGENTS.md) 的 2026-11-08 用户裁定，不再使用 Hermes 复审口径。卡面由用户手动转交，不自动建立执行会话或联络执行者，也不要求并行 Agent。

## 6. 模型与费用

交付软件本身不必内置另一套模型后端。IntegrateCraft 的 dsh Agent 已具备统一模型入口，软件应先作为受控工具使用。增加内嵌 Agent 循环会增加任务上下文、费用、停止与审计的接缝，应有明确必要性才评估。

Craft Anything 的内置重建 Agent 可作为内部辅助研究选项；它能生成一个项目，不会自动补齐该项目的页面接口、保存确认、平台接入和最终验收。具体差距见 [接入评估](../参考/CraftAnything-IntegrateCraft接入评估.md)。

模型真实验证按届时卡面授权执行。零模型工具往返先证明接线正确；不能把付费调用当作探测错误字段的替代办法。
