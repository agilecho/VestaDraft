## 编辑、保存与重开

```mermaid
flowchart LR
    A[原件或原生工程] --> B[codec装载与校验]
    B --> C[EngineV2命令与历史]
    C --> D[当前完整capture]
    D --> E[唯一原生writer]
    E --> F[CLI受控写出主文件及资源]
    F --> G[独立读取与新进程重开续改]
```

`prepare`产生带来源和目标约束的typed候选；在核实版本、身份、资源、预算和期限后才提交。原子批次失败不保留半成品，旧doc/epoch/revision、旧资源或过期候选不能沿用到新生命期。冲突、取消、拒绝、关闭及EOF等结果按实际状态清理，不能用返回零或文件存在替代这些断言。

[native_vesta_v2](../crates/codecs/src/formats/native_vesta_v2.rs)是当前唯一writer，产生主文件字节及依赖映射；它本身不写文件、不暗中回退，也不赋予Saved权限。主文件与相邻`.resources`中的manifest/blob构成工程；所需依赖来自实际闭包，读取时校验其内容与归属。文件中的VESTA版本头不代表已实现任意原版格式互通。

CLI的[paths](../apps/vestacraft-cli/src/paths.rs)负责限定根、观察目标基线及实际发布。已有文件外部变化会触发冲突而非无声覆盖；新工程必须能在原输入移开、旧进程销毁后仅靠工程制品重开，继续修改并保存。重开刷新运行身份，普通字面内容和合法别名关系保留。

原生工程字节成功写出仍报告`hostSaved=false`。真实宿主Saved需要适用的宿主确认；伪HostAck、错误authority/owner、token或过期lease不能使工程进入Saved。个人空间写入和用户页面整链由后续任务承接。

## Source7、Field和Graph2为何分别校验

Source7同时保存当前可编辑状态、完整来源及持久身份。冻结schema对应的22根、501属性等清单用于约束生成覆盖；schema校验之外还检查角色种类、owner/scope、定义/引用和语义关系。这些静态数字不能单独证明实际保存/重开正确，必须结合真实工程及反例。

资源的逻辑ID与内容SHA独立：相同字节可以有不同用途和不同逻辑身份。Field还绑定数据布局、轴序、精度、边界和具体use/owner/descriptor；即使blob字节相同，错用途或错归属仍被拒绝。相机、层、热参、隐藏/标签选择和边界latent状态属于完整持久状态，不能只保存画面上当前可见的部分。

Graph2检查原件之间的实际递归闭包、路径与顺序、重复边、跨度和共享预算；循环、缺件和超限必须拒绝。已接入的density/texture、ORFFE、RIETAN、GAMESS、FEFF等来源按各自合同和命名资格处理。未知或未取得资格的数据可以保留来源或拒绝活动安装，不能伪造科学结果。它不是任意文件目录的无限递归打包器。

## CLI与接口边界

当前CLI包含`commands`、`serve --stdio`、`inspect`、`run`等原生入口，文件操作要求显式`--root`，输入/输出参数以main.rs为准。NS2用于同一serve生命周期中的真实载入、编辑、资源和保存操作；不能从一次inspect拿运行ID，再传给另一个新进程冒充同会话续作。inspect可作来源/状态诊断，run产生实际工程输出，二者不替代宿主确认。

共享描述中的外层操作、命令和格式数量各有范围；协议可承载的类型、实际实现的领域操作、已验证的生产者资格不能互相替代。P3的40项科学操作没有因P2-03完成而自动全部实现。
