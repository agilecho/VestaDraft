# 文件格式与兼容工程

输入是格式样本、兼容目标和领域模型；输出是可解释的导入、可持续的原生工程、正确导出与迁移。能识别文件头、能读部分内容、能完整回写分别登记。

## 建立中间模型

外部格式由 codec 解析成领域模型，编辑逻辑只操作领域表示。导出器消费同一表示和显式选项。不要让一个陌生格式的未验证字节散落到 UI 和命令处理器中。

为格式特性建立“读取/显示/编辑/保留/导出”表。例如陌生扩展字段可保留原始块，但修改相邻结构后还能否安全原样回写，需要另证；不能以保留字节代替理解语义。

## 导入步骤

1. 识别容器和版本，并说明扩展名与内容不一致的处理。
2. 在分配和读取前检查长度、偏移、计数、嵌套、解压和总预算。
3. 解析基础结构，校验引用、编码、单位与资源表。
4. 映射领域对象，保存无法表达部分的明确限制。
5. 生成独立文档，完整校验后替换当前工程；失败保留旧工程。

压缩包成员拒绝越界路径和不安全链接，防止覆盖宿主文件；嵌套归档有总预算。XML/文档类解析器的外部资源行为要核实，不能让导入暗中读取宿主或联网。

## 版本化原生工程

持久格式有版本、对象身份、单位、文档与资源。迁移先把原始结构转换到当前模型，再验证；对更高未知版本避免覆盖丢字段。损坏与新版本分别报错。

小工程可单文件；多资源工程可选目录或容器包，依据原子保存、可迁移性、随机访问、大小和现有生态决定。目录型保存需明确 manifest 与资源的提交顺序，不能只原子替换一个文件就声称全工程事务完成。

## 往返测试

按语义比较 `import(export(document))`：文本、对象、几何、关系、时间和资源是否相同。字节顺序、压缩时间戳等可以不同；原片和用户未授权修改的资源则按其保护契约核字节。

还要做“外部软件打开导出”和“本软件打开外部样本”，分别记录实际工具版本。第三方读取器是交叉证据，不能把同一有缺陷的 codec 同时当生产与唯一裁判。

## 导出与宿主保存

生成字节和宿主成功写入是两个阶段。导出选项固定页/帧/范围、尺寸、编码和资源处理；写入失败反馈到原命令。导出不切换当前工程身份。

支持取消时，临时输出清理并保留已有正式文件。重复请求先查实际完成结果，避免相同导出覆盖新内容。接 IntegrateCraft 时复用 [保存与恢复](../方法/06-工程文件与保存恢复.md)。

## 练习与交付

原生 JSON 工程加入版本 1，迁移一份旧版本样本，拒绝未知新版本写回。测试空文件、截断、重复 ID、非法数值、缺资源、路径越界和大长度声明。

交付 codec 边界、兼容表、迁移规则、可分发样本和语义预期。按实际实现选择格式，不把整个行业格式清单一次性写成支持范围。
