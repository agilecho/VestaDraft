# 软件研究与重建验证

输入是允许研究的目标与明确用户任务；输出是行为规格、领域约束、可实现范围和证据。研究目的是知道要实现什么、怎样判断正确，而不只是收集大量截图或反编译文本。

## 制定观察计划

先列问题：输入怎样变成状态、一次操作改变什么、保存保留什么、失败后怎样恢复。为每个问题准备可区分假设的最小输入，记录操作前提、动作、结果和环境。

例如研究“复制对象”的语义，观察新 ID、坐标偏移、父节点、样式继承和撤销；只看两个相似矩形不能解释这些规则。研究导入则比较原文件、页面结构、保存副本和重开结果。

## 证据等级

直接观察、确定性计算、源码推断、项目自述和未验证假设分开。接口出现在源码中能证明存在，实现范围仍要看执行路径与输入；某个样本成功只证明该范围。

行为研究用受控运行，结构研究读真实源码/制品，格式研究读样本与可核规范。需要第三方 API 或版本事实时查官方来源并记录日期；避免从记忆发明参数。

## 从观察到规格

把结果写成“在前提 X 下，动作 Y 应使状态 Z，并保留不变量”。补失败行为和可见反馈。涉及数值规则时给精确输入输出；未知规则用对照样本进一步缩小。

实现优先级按完整用户链决定。观察到某复杂能力而当前内核不支持时，记录依赖、可用替代和单独验证，不把它放进已支持清单。

## 重建策略

已有开源能力且符合目标时评估复用和薄适配；重建新实现时按领域规格自主实现。界面、领域操作、格式兼容和自动化接口分别评估，不以其中一项替代整体。

Craft Anything 可整理结构、证据与初版，常规源码阅读也可直接得出结果；按问题选择工具。Clean room/Deep 的实际限制分别遵守，模式标签不替代授权与运行隔离。

## 对照验证

同样输入和动作分别作用于参考和新实现，比较领域语义、保存/重开和可见结果；容许差异事先定义并说明原因。参考自身有 bug 时不要盲目复制，是否兼容按目标用户需求决定。

用新的未见样本检查实现是否只是匹配演示数据。独立预期不从生成程序的自报 JSON 直接取得。视觉相似高而计算错误仍失败；结构正确而关键交互不可用也应记录。

## 练习与交付

选择一个只包含创建、移动、保存的目标用户链，形成观察记录与可执行规格；新实现运行相同输入，逐项写一致、差异、原因和未测项。

交付证据目录、行为规格、能力边界、复用决定及对照报告。缺关键证据先安排小研究，不重复让 Agent “继续完善”却不明确缺什么。
