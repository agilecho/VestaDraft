# 自动化测试与故障诊断

输入是用户结果、接口、目标环境与已知风险；输出是独立预期、可复现检查和解释失败的证据。测试用于发现错误，数量和截图好看都不能替代用户链。

## 设计验证接口

软件应能读取领域状态、当前文档/修订、资源就绪和实际渲染。浏览器测试可以用稳定控件标识和领域检查；Agent 业务操作仍走正式软件命令。不要额外提供只在测试中生效的“成功保存”路径。

用固定 ID 生成器、时钟或随机种子隔离不相关差异，但真实集成保持真实运输与 I/O。控制变量的替身要有身份，不能把替身的成功写成真实环境通过。

## 组织样本

每条能力至少有正常样本和关键反例。样本预期来自用户需求、手工计算、外部读取器或独立检查，而不是直接复制生产函数输出。

领域测试核数据，codec 测试核往返，页面测试核同实例交互，平台测试核运输和持久化。选择本次新增及直接影响项，剩余全量在原定最终关口执行。

## 真实用户链

从一个新页面开始，Agent 创建指定对象→独立读当前页面→截图→用户手改→Agent 读到并继续改→真实保存→独立读文件→导出→销毁页面→重开续作。

同时记录文档身份、修订、工具结果和文件摘要。重开使用新的页面生命周期；测试不能把预期数据注入应用状态来制造重开成功。

## 渲染检查

稳定字号、字体和视口后比较有业务含义的区域。对时间、光标等动态部分预先确定容忍规则；遮罩规则本身要说明，不能把错误区域都排除。

像素差与感知相似度各有盲区。中文缺字、错误页码、坐标错误等用结构和局部断言共同检查；只在必要范围做图像阈值，不把一个平均分当领域正确率。

## 失败定位顺序

1. 核请求是否到达正确版本和实例，原始入参与返回是否完整。
2. 核 schema、文档/页面身份、编辑权与队列。
3. 核领域状态是否提交；若未提交，缩成最小命令复现。
4. 状态正确而画面旧，核资源、渲染修订和失效调度。
5. 页面正确而文件错，核序列化、宿主写入与保存确认。
6. 本地通过而镜像失败，核目标架构、依赖、bundle 与实际加载。

先查上下游契约，避免反复增加超时或让模型重做任务。修复原症状，确认它在旧逻辑失败、修正后通过，再做直接关联回归。

## 让验收器可靠

人为注入一个可解释的失败，验收器应非零退出并显示断言；断开服务不能变 skip/pass。超时、未执行和遗留 running 保持独立状态。审计只读旧证据，新轮用新目录。

对参数错误、迟到回执、外改、空间满和取消选关键异常，核具体状态与旧作品。不要用脚本硬写 pass 或把失败日志拼成新整轮。

## 交付

交付测试入口、样本与独立预期、环境指纹、正常/反例结果、未验证项及修复关联。通过范围写清页面、原生、Linux、现场设备等，不做跨环境推论。
