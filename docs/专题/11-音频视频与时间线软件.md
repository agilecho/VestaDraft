# 音频、视频与时间线软件

本方向要把时间、资源和异步处理设计成领域能力。时间线画得像编辑器，只证明 UI；真实裁剪、播放、混合、编码与工程恢复需要逐项实现。

## 时间模型

音频以采样位置表达精确编辑，视频用帧索引和有理帧率表达；时间线与素材各有时间基。裁剪、变速、关键帧和吸附定义舍入规则，边界先换算再比较，避免累计浮点误差。

轨道包含片段、源资源、源区间、时间线区间和效果。移动片段不改原素材；非破坏编辑用引用和参数表达。覆盖、重叠和空白区域由产品规则决定。

## 音频引擎

区分离线处理和实时播放。实时路径避免阻塞、无界分配和同步 I/O；UI 通过参数/消息更新。浏览器 `AudioWorklet` 用于独立音频处理执行环境，并需安全上下文，见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet)。

波形是音频的派生可视化，缓存可重建。增益、淡入淡出、混音和效果有数值定义；采样率与声道转换明确。播放可用不自动证明离线导出正确。

## 视频与合成

分离容器解析、解码、时间调度、合成与编码/封装。浏览器 WebCodecs 提供低层音视频编解码及异步队列，具体编码配置和设备支持要探测，见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API)。

维护解码与导出背压，限制同时存活的帧和缓冲，及时释放已消费资源。seek 到新位置后，旧解码结果不能更新当前帧；媒体未就绪时返回可解释的等待状态。

关键帧包含时间、值和插值；明确采样时刻、区间端点和缓动。UI 曲线与实际输出参数一致，不能只保存曲线控件的形状。

## 编辑命令

命令覆盖导入、轨道/片段创建、选择、裁剪、移动、效果、关键帧、检查和导出。返回源/时间线单位和当前修订，避免 Agent 把秒传成毫秒或帧。

播放头属于会话状态，素材/片段结构属于工程。导出任务固定快照、范围、编码与输出身份；期间用户继续编辑时，旧导出不得清除新 dirty。

## 资源与恢复

保存工程引用和相对资源，缺失素材可定位并重新链接；代理媒体和波形缓存能清理重建。浏览器内存桥、大资源流式传输和服务端编码的边界分别核实。

后台节流不能靠固定 sleep 修复。测试实际媒体就绪、播放/暂停、后台恢复、取消导出和页面重开。编码失败保留工程与已存在正式输出。

## 练习与验收

音频：固定采样率的已知信号做裁剪与 0.5 增益，核采样数、声道及幅值。视频：已知帧率的两段素材重排，指定帧叠加标记，核时长、帧时刻和导出内容。

至少一次由 Agent 操作当前时间线，人移动片段后工具读回；保存关闭，重开素材引用与关键帧仍在。自报“播放通过”不能替代独立信号/帧检查。
