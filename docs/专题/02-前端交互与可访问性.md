# 前端交互与可访问性

输入是用户任务、领域命令和可观察状态；输出是人可持续使用的编辑器。Agent 调通工具之后，选中、输入、拖动、撤销、焦点和错误恢复仍需按真实用户体验实现。

## 布局与状态

先列核心工作区：作品视口、工具栏、对象/页面/轨道导航、属性区、状态与保存反馈。把领域数据、选中状态、临时拖动、面板布局和异步任务分开。组件通过订阅读取状态，操作发命令；避免每个组件各藏一份可修改文档。

选框和属性面板从相同选择集合派生。Agent 添加对象后，UI 可以按明确产品规则选中和定位；不要伪造一个只在工具面板出现的对象。属性编辑失败要恢复输入或保留可修正值，并显示具体原因。

## 指针与坐标

将屏幕点先减去画布布局偏移，再通过视口变换的逆矩阵换算为世界点。命中测试、拖动、吸附和 Agent 坐标均使用约定的领域坐标。DPR 仅参与 backing store 与显示换算，不改变工程数值。

指针交互分为开始、预览、提交、取消。捕获指针后仍处理取消和页面失焦；拖到边缘松开也能结束。按键 Escape 取消预览，最终只提交一次领域操作；需要连续提交的工具明确其撤销分组。

## 文字与键盘

中文输入按组合输入生命周期处理，不能在拼音尚未提交时触发保存快捷键或重复插入。快捷键要尊重焦点：在数值框/文本框输入时，Backspace 不能顺带删画布对象。

定义焦点在工具栏、画布、导航树、属性表和对话框之间的转移；对话框关闭后回到可解释的位置。键盘操作与鼠标操作调用同一命令。可见快捷键说明与实际支持保持一致。

## 可访问性

优先使用有语义的 HTML 控件。Canvas/自绘 UI 需要可访问的名称、对象导航、状态反馈与键盘等价入口，不能只有像素命中区。复杂组件的角色、键盘和焦点模式参考 [W3C APG](https://www.w3.org/WAI/ARIA/apg/patterns/)。

错误应在关联位置说明，长任务报告进度和取消入口。颜色不能是唯一状态标识；文字、图标与实际 disabled 状态一起表达。工具可操作不等于对人可访问，两类验证分别保留。

## 编辑与保存反馈

操作中的预览、已提交、未保存、保存中、保存失败、已保存应可区分。工具成功不自动清除保存错误；真实保存成功才更新保存状态。外改冲突要有实际有效的重新载入/另存副本操作。

布局切换与组件重建不得丢失工程、未保存状态或正在进行的编辑。响应式布局明确面板收起顺序；缩放窗口后再次检查关键工具可达和画布坐标。

## 练习与验收

用鼠标添加和移动形状，用键盘选择、移动、撤销；Agent 检查应读到同样坐标。用中文命名并编辑属性，再在输入框中按删除，画布对象应保留。

测试小窗口、高 DPR、键盘导航、失焦取消、保存失败和重试。检查 UI 状态与领域状态，配真实画面。避免把“按钮存在”或 CSS 快照当成交互通过。

交付用户流程、快捷键/焦点表、UI 状态模型和关键交互证据。具体渲染边界继续读下一专题。
