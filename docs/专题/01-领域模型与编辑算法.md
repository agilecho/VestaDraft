# 领域模型与编辑算法

输入是目标用户链、样本和精度要求；输出是领域状态、可执行操作、不变量、事务/撤销和可持久化模型。先完成可测试的领域闭环，再让 UI 和工具调用它。与 [命令架构](../方法/03-命令内核与多端架构.md) 配合阅读。

## 建模步骤

1. 列实体及身份：文档、页、节点、轨道、素材、表格等。标题、列表位置、屏幕坐标不作持久 ID。
2. 列所有权和引用：节点属于谁、资源如何引用、删除后哪些引用应拒绝或更新。
3. 列值类型与单位：坐标、角度、颜色、长度、时间、采样、公式值分别建类型，确定有限数值和范围。
4. 分开持久状态、会话状态、派生缓存。例如形状几何要保存，当前 hover 不保存，包围盒可重算。
5. 写不变量及失败动作，再定义能够维持它们的操作。

画布例子的不变量可以是：文档尺寸为正有限数；对象 ID 唯一；宽高为正；父子关系无环；选择集合只含存在对象；每次成功的持久修改增加修订。文档模型保存世界坐标，视口变换放会话状态。

## 单一修改入口

建议一条命令经历“解析参数→定位文档/对象→检查修订与权限→计算变更→验证不变量→提交→发布状态变化”。检查失败保持提交前状态。读取和渲染不得在背后修改文档来补字段。

命令处理返回结构化的变更范围，例如对象 ID、前后修订和受影响区域；UI 依此刷新。手动操作转换为同样的领域命令，Agent 不走另一套业务函数。拖动过程可以用预览状态，结束时提交一个可撤销操作。

## 事务和批处理

原子批处理在临时状态执行全部检查，全部成功后一次提交；任何步骤失败丢弃临时结果。部分继续型批处理逐步提交并返回每项状态，不能使用同一“原子”标签。

跨文件、数据库或远程服务的操作，明确提交点和补偿方式。不要先修改内存再等待一个可能失败的外部调用，却没有恢复策略。大型数据可用写时复制/增量变更，避免每次都复制全部资源。

## 撤销策略

| 方案 | 适合 | 需要控制 |
|---|---|---|
| 全量快照 | 小文档、原型和易序列化模型 | 内存上限、资源引用与快照复制成本 |
| 正反操作 | 明确定义的几何、文本或属性操作 | 逆操作保存旧值、对象生命周期和批处理边界 |
| 增量补丁 | 较大树或结构化文档 | 路径稳定性、格式版本、重排和冲突 |

撤销恢复业务状态和修订关系，不能恢复已释放的外部句柄。撤销后新编辑应清理不再可达的 redo 分支。保存状态应比较当前内容/历史位置或既有原生修订，不能只按“撤销按钮点过”判断 dirty。

## 选择领域算法

先选正确的领域表示，再选加速结构。大量图形可先有正确的线性命中，再根据测量引入空间索引；表格先建公式语法与依赖关系，不能靠遍历字符串替换；三维需要拓扑与几何一致性，不能用 UI 层坐标列表替代。

复杂算法优先评估已有适配内核，核 API、数据模型、目标平台、许可证声明和精度。缺少能力先做带输入输出断言的小研究，不能让模型虚构一个求解器或把未计算结果标为成功。

## 练习与验证

对一个矩形完成新建、绝对移动、改色、删除、撤销与重做；比较命令前后完整领域状态，保证失败无部分修改。再加入父子节点，验证拒绝循环和删除引用处理。

检查非法 ID、非有限数、负尺寸、修订冲突、空 batch 和 batch 中途失败。不要只断言回调被调用；断言数值、对象集合和不变量。

交付领域模型说明、操作契约、状态转换和精确样本。对应场景扩展见办公、图形/CAD、音视频和数据工具专题。
