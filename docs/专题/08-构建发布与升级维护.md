# 构建发布与升级维护

输入是已实现的用户链、依赖和目标运行环境；输出是可复现、可定位、可恢复的交付包。开发机运行成功与交付环境可用分别验证。

## 构建说明必须可执行

在目标新项目中维护 `BUILDING.md`，给出前置工具的精确来源/版本、目标架构、依赖锁、资源输入、构建命令、产物位置和验证命令。命令中的 package 名和路径必须是该项目真实值。

对 Rust 工程常用的 `cargo build --locked`、`cargo test` 和 Web 打包器，对 npm 工程的锁定安装与脚本，都在选定工具后固定；不把本目录写成适用于所有软件的同一套命令。

## 输入与产物清单

| 类别 | 应记录 |
|---|---|
| 源码 | 仓库、提交、允许的补丁和实际文件摘要 |
| 依赖 | 锁文件、特性、目标平台及系统库 |
| 外部输入 | 字体、语言、模型/素材、工具二进制及来源 |
| 工具链 | 编译器、绑定生成器、打包器和优化器 |
| 构建环境 | 镜像摘要、平台、环境配置中的非秘密部分 |
| 产物 | JS/WASM/CLI、压缩资源、许可、摘要与版本映射 |

获取失败保持失败，不能随手改成 latest。密钥不写进构建清单、镜像层或客户端。已有制品身份按项目规则继续使用，不因文档更新重建一切。

## 多目标与资源

原生 CLI 按 Linux/x86 等实际目标构建；Web 验最终资源路径、MIME、缓存、字体、WASM 和 Worker。压缩旁文件也是实际响应的一部分，源码更新后应与主文件一起受指纹控制。

构建缓存分配具名目录和配额；与用户工程、部署制品区分。缓存损坏可在授权范围独立处理，不能清理其他任务资源来“修构建”。

## 升级及数据迁移

升级至少考虑程序版本、配置版本、工程格式和插件协议。旧数据有迁移路径，更高未知格式避免写回。升级前保留可识别备份和恢复入口；恢复旧程序时确认它能否读新文件。

静态包缓存使用实际内容身份。新包启动不复用旧接口缓存，旧页面不能向新实例提交过期请求。应用重启恢复任务时核实际状态，不重复发付费或有副作用的提交。

## 发布与运维

健康检查分进程存活、工具就绪和业务可用。采集必要非秘密诊断：版本、任务、阶段、错误、用时、资源和停止原因。日志有容量与保留策略，用户作品不因调试而额外外发。

回滚针对具名版本与配置执行，记录对数据的影响；生产发布、签名和外部变更按当前授权。原型研究不自动增加发布级签名、现场或全平台要求。

## 练习与交付

在干净目标环境按文档重建小编辑器，核 manifest 与实际加载。更新一个资源后核缓存身份变化；让一份旧工程迁移，再尝试未知新版本，验证拒写不损坏原件。

交付安装/启动/停止、构建、升级/回滚、故障诊断和产物清单。现有平台集成见 [接入指南](../接入/01-IntegrateCraft接入与复用边界.md)。
