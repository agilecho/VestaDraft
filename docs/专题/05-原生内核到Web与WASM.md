# 原生内核到 Web 与 WASM

输入是现有引擎、依赖图和目标部署；输出是浏览器可运行的领域能力及薄页面接口。已有纯 Web 内核可直接使用；已有原生内核先评估可移植边界，不默认重写。

## 选型决策

| 现状 | 优先评估的路径 |
|---|---|
| TypeScript/JS 内核与 Web UI 已成立 | 保留，补正式命令/工具与宿主契约 |
| Rust/C++ 等内核与平台 I/O 分离 | 核 WASM 目标，复用解析、计算与序列化 |
| 内核大量依赖系统进程/GPU/文件 API | 拆平台层，比较浏览器替代与受控服务端能力 |
| 原生能力无 Web 对等实现 | 明确需要远端服务的范围、延迟、费用与隔离 |

从最小真实文档的打开、一次编辑和导出开始验证。桌面 app 编译成 WASM 不等于系统调用、字体、线程和对话框都成立。

## 移植实施顺序

1. 画依赖图，把领域逻辑和平台 I/O 分开。
2. 对每个依赖核目标支持、特性开关、构建工具及许可证声明。
3. 在领域层编译目标，删除 UI 依赖倒灌；平台函数通过窄接口注入。
4. 让浏览器通过内存字节打开/保存，避免把虚拟路径当宿主真实路径。
5. 封装已有控制处理器为异步页面接口，原错误和 batch 语义保持。
6. 用真实字体、资源和导出核内容，再接工作台。

构建命令按实际工具链写入该项目 `BUILDING.md`：目标、features、生成绑定、静态打包、资源路径和产物摘要。文档示例中的工具版本不能替代锁定输入。

## JS 与内核边界

小参数走结构化数据，大媒体使用有所有权约定的字节/句柄。明确分配、释放、复制和生命周期；避免每帧序列化全工程或重复 Base64 转换。

错误在内核转成结构化结果或受控异常；Promise 只在实际内核完成时解决。打开文件是入队的原协议，应由上层继续等待文档就绪。异步回调带实例身份，页面销毁后拒绝迟到结果。

## 线程与部署

优先证明无共享内存路径可用。确需共享内存时，文档需满足安全上下文与跨源隔离要求，并检测实际 `crossOriginIsolated`，见 [MDN SharedArrayBuffer](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/SharedArrayBuffer)。不要为了一个依赖自动给整个工作台改隔离头。

核 iframe 的响应头、父页策略和所有资源，不仅本地直开页面。Worker 路径、相对资源、CORS、CSP 和缓存以最终托管地址验证。失败应报告具体缺项，并保留原文档。

## 文件桥与消息

同源可调用页面公开 API；需要消息桥时，发送指定 origin，接收校验 origin、source、schema 与请求身份。传输 ArrayBuffer 后原持有方不能继续使用其已转移所有权的缓冲，见 [MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)。

消息类型只能进入已定义的控制器，不提供任意函数名执行或任意脚本求值。新软件自主定义契约；接现有软件保留原生协议，不照抄其他款字段。

## 练习与交付

同一小文档在原生与 Web 执行同一命令序列，按语义比较状态与导出。测中文、异步打开、重复实例、导入取消、资源失效和最终静态地址。

交付依赖可移植性表、最小补丁、页面契约、构建锁与真实浏览器证据。只有纯解析器可 WASM 时，产品能力登记到解析器，不登记整个编辑器已 Web 化。
