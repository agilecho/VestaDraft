# 安全、扩展与协作边界

输入是软件部署形态、用户与扩展能力；输出是由实际执行入口强制的能力范围。单机工具、学校平台和桌面协同版的要求不同，先采用目标项目已有规则，不把一种部署的全部治理复制给另一种。

## 分清信任来源

用户指令、文档内容、网页、插件、Agent 输出和模型响应分别看待。文档里的命令文本是材料，不是额外授权。错误、提示词和界面按钮不能替代服务端或 OS 拒绝。

列出实际入口：UI、页面 API、CLI、MCP、插件、文件导入、资源 URL、后台任务和预览。每条变更最终落到领域命令、文件写入、进程或网络，策略在这些真实接缝生效。

## 工具权限

工具声明读写、启动程序、访问网络、运行目标代码、设备变更等副作用；运行时依真实身份和任务校验。只读查看覆盖配置修改、审批回答、导入写盘和后台启动，不能只限制文件编辑按钮。

工具列表隐藏不代表不能调用；别名、batch、嵌套命令和动态工具都需要检查。拒绝未识别能力，返回可理解的原因和允许的替代路径。

## 文件、资源与执行

路径保护覆盖符号链接、父目录、归档成员、嵌套资源和保存目标；使用现成安全 I/O 和 OS 沙箱。容器内子进程也不能因此读到平台秘密或所有技术目录。

用户代码、宏、插件和目标程序按其实际执行能力隔离。进程不继承多余凭据，stdout/stderr 有上限，停止终结所属树。网络出口按目标部署策略校验，重定向和子资源同样受约束。

## 插件接口

先判断是否需要可执行插件，很多扩展可以用受约束的命令/数据实现。可执行插件定义版本、能力声明、配置、生命周期和卸载清理，错误不能破坏主文档。

插件 UI 与宿主共享什么对象要明确；不向不可信插件暴露任意 eval、全局 Session 或平台管理实例。动态命令与静态命令走相同校验。升级后协议不兼容明确拒绝。

## 单写者与多人协作

同一用户的人机共编首先解决单写者协调、修订和外改；这是本项目当前的主要需求。多人实时协同是额外能力，涉及操作顺序、离线变更、合并、撤销和权限传播，需另定模型。

可以选择服务端序列化、OT、CRDT 等方案，但需要依据领域操作设计和验证；简单增加 WebSocket 不能得到正确协作。未实现多人协同时明确禁止双写，冲突保留双方内容。

## 练习与交付

通过直接调用和批处理尝试越界文件、禁用工具、只读写入、旧修订和过期页面。使用无秘密的受控探针；拒绝应来自实际入口，原作品保持。

交付信任边界、能力表、策略位置、关键反例与未覆盖路径。IntegrateCraft 的具体身份、额度和审计规则继续看权威文档。
