# 接入到项目的 Craft 的技术要求

> 整理日期：2026-11-07。本文汇总 IntegrateCraft 已确认的 Craft 接入技术要求，供接入评估、发卡、施工和验收引用；不是施工卡，不新增开工、构建、模型调用或合并授权，不改判历史已接受成果。

## 1. 适用范围与依据

适用于接入 IntegrateCraft 的 Craft 软件。共同要求统一到用户结果，各款的命令、工程格式、页面接口、保存协议和必要补丁按锁定版本的真实能力适配。

业务与架构遵循[文档权威顺序](../../README.md#权威顺序)，主要依据为：

- [PRD 第 10.10 节](../../PRD-v1.5.md#1010-专业软件工作台p0首发接-3-款)：SW-1～SW-9。
- [技术方案第 2 章](../../技术方案.md#2-硬约束)、[第 9.6 节](../../技术方案.md#96-软件工作台与-agent-操作软件)、[第 13.3 节](../../技术方案.md#133-版本受控rel-1)：接口、隔离、工作台、存储及版本受控。
- [软件接入方法：以 WordCraft 为默认基线](软件接入方法-以WordCraft为基线.md)：复用已有实现，只补本款差异。
- [决策确认单](决策确认单.md)：D3-10 保存与导出不自动下载，D3-15 不采用覆盖矩阵，D3-16 新增功能单测及分阶段验证，D3-21 复用方法，D3-70 Agent 驱动 Web 并实时显示结果。
- [执行者手册](执行者手册.md)第 7、10、10.1、11 节：质量关口、契约核实、独立接手及实施边界。

当前软件、施工顺序、基线、资源、预算、次数、停报及剩余验收，以[阶段 README](README.md)、已确认决策和当前卡续办节为准，本文不另存状态快照。发现依据冲突时报告文档方，不自行改变产品规则。

## 2. 最终必须交付的用户结果

1. **平台内打开和使用。** 用户从现有工作台打开软件，在 dsh 内嵌 Web 页面使用；Agent 自动获得该软件的操作能力，用户不需要另外安装或配置。
2. **Agent 操作当前 Web 工程。** 真实工具调用修改当前页面持有的工程，页内内容与可见画面自动更新。用户看到的是同一工程的实时结果，之后还能继续手动编辑。
3. **三种视图连续使用。** 支持 Agent、Agent+WebGUI、WebGUI；切换只改变布局，不卸载页面、不丢未保存编辑、不打断进行中的操作。第一次默认 Agent+WebGUI，按现有机制记住用户上次的模式。
4. **作品进入本人个人空间。** 工程保存、另存和导出使用真实产物，个人空间写入成功后才确认；关闭后显式重开，内容与此前保存结果一致。
5. **关页续作有真实交接。** 页面未加载或实际关闭后，按本款已核实的官方 CLI/MCP 能力继续操作同一已保存作品；再次打开 Web 能读到续作结果。切到 Agent 视图不等于关页，不应另起引擎修改页面仍持有的工程。
6. **权限和计量沿用平台。** 只读写本人被授权的空间，不扩大软件工具的权限；真实模型调用走平台网关，费用与限额归属沿用现有链路。

CLI/MCP 单独成功、生成文件、静态首帧、图片预览，以及手动刷新或重开后才看到结果，都不能替代第 2 项。CLI 可以承担必要计算；页面开启时，计算结果必须交回当前页面并实时呈现。

上述是最终接入结果，具体分段何时验证由当前卡规定；摸底卡只报告能力、缺口和最小补丁方案，不在摸底范围内补实现或登记“接入完成”。

## 3. 接入前先核实真实能力

在当前卡允许的范围内核实，并保留可复查的依据：

| 核实对象 | 必须回答的问题 |
|---|---|
| 版本与来源 | 使用哪个上游提交/发布件、依赖锁、工具链和补丁？本地源码、构建输入与实际运行件是否一致？ |
| Web 运行 | 网页能否构建和加载？依赖什么图形能力、字体、静态资源或宿主环境？就绪信号、加载失败和耗时是什么？ |
| 页面控制 | 是否已有可调用 API、消息通道或控制处理器？命令能否作用于当前工程并立即更新画面？ |
| 官方 CLI/MCP | 实际工具清单、参数 schema、返回与错误形状、支持的读写根/沙箱选项和文件路径来源是什么？ |
| 文件与保存 | 如何打开、取得工程/导出字节、确认宿主保存？接口返回代表已完成、入队还是仅交付字节？ |
| 浏览器存储 | 正常保存、自动保存、恢复/panic 路径是否写入浏览器持久存储？能否使用已有宿主或内存模式？ |
| 中文与格式 | 中文文件名、正文、字形、导入、导出及重开分别支持到哪一步？哪些仅有源码线索、尚未实测？ |

关键能力用锁定源码/schema与实际运行结果核对，不把旧说明、示例参数或其他 Craft 的成功当作本款事实。未知能力先做有边界的摸底；构建、模型及服务启动必须在卡面授权内进行，不能以探测命令名义越过关口。

## 4. 架构与接口要求

### 4.1 复用现有接入框架

默认沿用 WordCraft 最终方法及之后已合并的共用实现：软件目录与启停、文件打开路由、三种视图、工具运输、个人空间、安全读写、命名、冲突、保存确认及验证入口。

已有页面 API 直接接用；缺页面 API 但已有控制通道时，只补薄接口，转交原有命令处理器。保持原生编辑命令、文档模型和计算语义，不为接入另造编辑引擎。不能直接套用共用实现时，卡内说明具体契约差异、最小增量及验证方法，不默认为每款新建完整服务、会话/票据系统或质量执行器。

现有代码入口供定位，实际取用以当卡基线为准：

- `dsh/plugins/software/catalog.mjs`、`startup.mjs`、`client.jsx`：注册、就绪、工作台和页面接线；变更客户端时同步生成的 `client.js`。
- `service.mjs`、`channel.mjs`、`coordinator.mjs`：现有工具运输与工程协调。
- `software-files.mjs`、`coordinator.mjs` 中的 SpaceFiles、`native-paths.mjs`：命名、个人空间、外改检查和安全读写，不另复制裸文件系统守卫。
- `word-page.mjs`、`word-tools.mjs`及其他已接软件：参考职责划分与接缝，按本款协议适配，不逐行照抄历史实现。
- `craft/<软件>/`：锁文件、补丁、构建入口、制品及说明的现有组织方式。

### 4.2 保持真实命令契约

- Agent 操作软件走软件自己的页面接口、命令通道或官方 MCP，不用模拟鼠标键盘替代命令接入。浏览器自动化可以用于验收用户界面。
- 工具名可以复用通用约定，命令编号、参数、返回层级、错误对象与异常按本款实际 schema；原生原子 batch 保留原语义，不能改成逐条循环后仍宣称等价。
- 页面 API → adapter → 客户端 bundle → 服务端 → 个人空间的字段必须贯通；新增字段核对服务端接受范围，不能在中途丢弃后仍返回成功。
- 命令返回、排队完成、页面就绪、导出完成和宿主落盘确认分别判定；等待真实完成信号，不用固定等待时间冒充完成。
- 同一时刻同一工程由一个引擎修改。沿用现有协调和串行机制，核实页面、无头引擎及文件交接，避免串稿、重复执行或相互覆盖。
- CLI 的 roots、autosave、author 等选项只传本款锁定版本确实支持的参数；缺读写根选项时使用已验证且当卡允许的平台路径、沙箱或挂载约束，不能静默放宽权限。

## 5. 工程、保存、另存与导出

### 5.1 文件身份与真实落盘

- 分清当前工程、导入源、另存目标与导出副本。身份根据真实工程与操作结果判断，不靠同名、后缀或旧路径猜测。
- 打开和保存沿用个人空间路径、安全读写、中文命名及重名处理；外部已修改的文件拒绝静默覆盖，提供有效的重新载入或另存副本处理。
- 手动保存、自动保存、关闭前写回和工具保存都核宿主真实写入结果。单文件沿用已定 60 秒自动保存与关闭前写回；库型软件按其真实持续写回契约处理。
- 宿主交付字节、HTTP 成功或下载已发起不等于已保存。只有个人空间真实写入成功，才确认对应快照已保存并按本款协议更新路径/状态。
- 保存期间又发生编辑时，先前快照的成功确认不能清掉后续修改；失败、冲突或超时保留未保存内容，不显示假成功。具体确认字段与实现复用已有能力，必要差异逐款核实，不统一强制 FigCraft 的专用协议。

### 5.2 导出与重开

- 保存与导出都写入个人空间，不自动触发浏览器下载；用户需要带走文件时从个人空间下载。
- 导出副本不能误重绑当前工程路径、清掉工程未保存状态或覆盖导入源；不能将 PNG/PDF 等导出字节写回工程文件。
- 界面和工具入口都按当卡要求验证，检查实际编码、正文/结构/必要画面及目标路径，不能只验扩展名或格式白名单。
- 关闭页面、CLI/MCP 续作与 Web 重开必须消费彼此实际写出的同一路径、同一作品；不能用驱动自行生成的替代文件证明往返。
- 导出后核对工程身份和实际内容是否符合预期；按本款格式判断允许变化，不机械要求库文件或工程所有字节始终不变。

## 6. 隔离、浏览器存储与权限

1. 文件接口、页面桥和 CLI/MCP 的权限都由实际服务端、路径及运行环境约束；不能只靠隐藏按钮、模型说明或客户端自报用户身份。越权、越根、只读与空间不足等拒绝按当卡相关场景验证。
2. 软件工具不得比本人正常工作环境获得更多权限；不能读取其他用户数据、实例令牌、平台配置或供应商密钥。没有 roots 参数的软件须实测其替代约束。
3. 工程、库及作品恢复副本不持久保存在 localStorage、IndexedDB、OPFS 等浏览器存储；偏好可保留。检查正常、自动、恢复/panic 等实际入口，已有 host/内存模式优先使用，不将某款 URL 参数照抄为通用协议。
4. 保留平台现有用户站点隔离、退出登录清站点数据及受限预览机制；退出清理不能替代运行期间不留作品恢复副本的要求。
5. 软件保存和导出受现有个人空间配额约束；Agent 的模型额度在网关拦截。新增接入不另造一套费用或额度判断。
6. 秘密不进入命令行、客户端、用户容器、日志或证据；真实模型凭据仅按当前卡的前置和授权使用，不为接入或文档检查另发付费冒烟。

LightCraft 的照片库锁、原片保护、永久删除限制及 XMP 边界按其适用范围保留，不自动推广给所有软件；其他软件已有的专用保护也不能因复用通用框架而删除。

## 7. 中文、界面与产物可用性

- 沿用当前卡的界面与中文要求；中文指令、文件名、工程正文、画面和导出分别验证。翻译资源存在不等于字形可显示，页面显示正确也不等于导出内容正确。
- 中文字体的来源、许可、构建输入和实际加载方式可追溯。Web 与 CLI 的字体环境分别核实，不能以开发机系统字体回退证明交付环境具备中文能力。
- 完整字体、独立静态交付、首帧注册等已定条件按具体卡执行；未经裁定不裁剪中文覆盖、不靠关闭优化或降低门值绕过构建要求。已批准的英文界面等差异沿用原裁定。
- 工作台有加载提示与实际就绪/失败判断，记录加载耗时；静态首帧通过不能代替工程操作、字体和内容验收。
- 当卡要求的导入/导出格式以真实样本验证。文档核正文和结构，图像核尺寸/图层/像素等相关结果，音视频或工程设计核其对应内容与属性；选与用户结果有关的独立预期。

## 8. 构建、补丁与运行版本

1. 锁定上游提交/发布件、依赖锁、必要工具链、字体及补丁；构建按本款真实命令执行，保存日志、退出码、制品路径、字节数和摘要。
2. 不修改 dsh 共享上游源码；Craft 只按卡面允许的最小补丁施工，补丁放本项目 `craft/<软件>/patches/` 并准备上游提交材料，保留许可和上游说明。
3. 构建体积、磁盘、内存、重试次数与目标架构以当前卡和已确认裁定为准。不存在适用于所有 Craft 的统一 WASM 门值，也不从旧卡继承工具链、预算或资源权限。
4. 交回前核对源码、生成的客户端 bundle、锁文件、补丁、Web/CLI 制品和 runtime 实际加载版本。改过代码而仍加载旧包，只能算旧包的结果。
5. Mac 开发、容器与现场 x86 分别说明证据范围；项目交付目标沿用 x86，不能用 Mac/ARM 成功追认 x86 通过。现有分阶段安排保留，不额外增加发布级要求。

## 9. Agent 可用性

软件接入不仅提供工具入口，还要让 Agent 能正确完成当前卡的用户任务：

- 复用平台下发、中文工具说明、Skill 和正确操作提示；软件会话内修改作品走该软件工具，普通会话行为沿用现有规则。列目录、查看文件或询问用户不等于绕过软件修改。
- 工具说明与实际 schema、路径来源、保存/导出行为一致；命令发现与返回按本款真实能力和上下文需要提供，避免无界输出挤占后续任务上下文。
- 工具错误要表达真实原因及允许的处理方式；同一任务中看到错误后自行纠正，与重新发送用户任务分开记录。
- 真实模型自主任务只在当前卡授权、零费前置及后台就绪后进行，沿用累计预算、次数与核账要求；不能用受控模型结果代替真实模型通过，也不能用一次模型误用直接判定整个接入机制失败。

## 10. 测试与证据要求

### 10.1 按改动和阶段执行

- 新增适配逻辑、接口行为或守卫补相应单测；既有上游能力与共用功能复用已有测试，不因接一款软件重补整套，不按新增文件数量机械建测试。
- 施工和整改期间只运行新增或直接关联的测试，说明实际影响依据；直接相关的真实往返和关键异常随改动验证。其余既有回归留最终集成关口统一执行，不按历史失败名单逐项提前重跑。
- 接入完成后用真实集成 E2E 验用户结果，单测、源码分析和替身宿主不代替整链。父卡完整 quality、真实模型、合并后及 x86 等既定关口按原安排保留；未执行的写“未验证”。

### 10.2 完整用户链的判据

按当前卡范围贯通：**真实工具修改当前 Web 工程 → 页内内容与画面实时更新 → 保存确认 → 实际文件读回 → 界面/工具导出 → 导出内容核对 → 关闭/续作 → 显式重开核内容**，并覆盖直接相关的失败与恢复。

每一步写清操作、独立预期、实际结果和证据。内容断言来自任务要求或已核实的独立解析，不用执行端自己的“成功”字段互相证明；文件存在、HTTP 200、测试数量、open 返回或单张截图都不足以证明整链。

保存失败、外改冲突、迟到确认、错误路径、坏输入等按本款新增逻辑与当前卡风险选择必要反例；不机械复制每款所有历史事故。需要证明“不下载”时，动作前监听下载事件并检查结果。

### 10.3 证据必须可判失败

- 检查项初始为未验证，完成对应断言后才能记通过；异常、错误返回、超时、缺产物和内容不符必须落证据并使对应验收失败，不能吞错或硬写 pass。
- 每轮使用 `output/阶段3-原型完善/<卡号>/<新目录>/`，保留原始日志、截图、产物、内容核对、指纹及回执；旧失败和已接受成果不覆盖，不拼接历史日志充本轮最终关口。
- 逐项区分通过、失败、未验证，说明受控、本地、真实浏览器/服务、模型和 x86 的证明力边界。自验、独立复审和 Git 合并分别记载，不能互相替代。
- 不新建覆盖矩阵、mutations.tsv 或颜色门；直接按卡面验收点保留实际结果和证据。本文的要求整理不要求重开、重跑历史已接受成果。

## 11. 每款接入应交付的材料

具体路径和命令由任务卡明确，至少能让全新施工会话找到并核验：

1. **能力与差异依据**：锁定版本、真实接口/schema、错误返回、已验证能力、缺口和最小补丁范围。
2. **接入实现**：注册与工作台接线、必要页面/工具适配、文件桥、保存/导出及路径保护；明确复用了什么、补了什么。
3. **可复查制品**：锁文件、补丁、构建/使用说明、制品摘要及 runtime 身份；已接受依赖可引用，不要求无影响重建。
4. **验证入口**：新增单测、直接关联回归、真实用户链脚本/夹具，以及从新会话恢复环境所需的准确命令、前提和失败处理。
5. **完整回执**：本轮分支/提交、改动范围、逐项结果与证据、未验证边界、停报、资源保留/关闭及费用记录。
