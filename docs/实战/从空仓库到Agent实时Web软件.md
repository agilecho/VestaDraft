# 从空仓库到 Agent 实时 Web 软件

本实战把各方向串成一条可执行的设计和验收路线。示例是一款小型二维画布编辑器：创建矩形、移动、改色、撤销、保存工程与导出。以下接口和文件布局是新项目示例，不是现有 WordCraft 参数，也没有在本轮创建或实现该软件。

已有项目从其真实接口接入，不为匹配示例重构。开始实施前遵守目标仓库与当前任务授权。

## 0. 固定用户故事和结果

用户打开 800×600 画布，Agent 创建中文标题“课堂示例”的工程，在 (40,50) 创建 120×80 的蓝色矩形，移到 (100,80)。用户拖到 (140,90)，Agent 读到它并改成红色。保存 `.craftdemo`，导出 SVG 和 PNG；关页重开后矩形仍红色、坐标 (140,90)，继续移动和保存成立。

第一轮不做复杂路径、多人协作或专业格式兼容。颜色固定为蓝 `#2563eb`、红 `#ef4444`。这些数值构成独立预期。

## 1. 确定项目形态

如果没有既有内核约束，示例可用 TypeScript 领域模型与 Canvas/SVG 实现；若已有 Rust 内核则核 WASM 路径。先在目标项目选定工具和锁版本，再写真实构建/测试脚本；本轮文档不安装依赖。

建议职责布局：

```text
core/        Document、Shape、命令处理、不变量和撤销
formats/     craftdemo 的读写与迁移、SVG 输出
web/         画布、属性区、状态订阅、正式页面接口
tools/       命令注册与官方 MCP/控制协议适配
host/        本地示例宿主或平台文件接缝
tests/       领域、格式、页面、真实宿主往返
docs/        范围、架构、接口、构建、当前状态
```

依赖朝领域核心，内核不引用 DOM、模型 SDK 或平台账号。实际目录可遵循既有仓库风格。

## 2. 建模和命令契约

`Document` 保存 version、id、title、width、height、revision 和 shapes。矩形保存 id、kind、x、y、width、height、fill。当前选择、视口与拖动预览留在会话状态。

| 命令 ID | 输入 | 结果和副作用 |
|---|---|---|
| `document.new` | title、width、height | 新 documentId，初始 revision=0 |
| `shape.add` | documentId、矩形几何与 fill、expectedRevision | 新 nodeId；持久修改加一修订 |
| `shape.move` | documentId、nodeId、x、y、expectedRevision | 设置绝对坐标；加一修订 |
| `shape.style` | documentId、nodeId、fill、expectedRevision | 设置颜色；加一修订 |
| `document.inspect` | documentId | 当前修订及完整矩形列表，不修改 |
| `history.undo` / `history.redo` | documentId、expectedRevision | 恢复业务状态并发布新修订 |
| `document.export` | documentId、format、revision | 对指定当前快照产生工程/SVG/PNG，不标记宿主已保存 |

修改前核文档、修订、对象与有限数值；失败保持旧状态。用 [契约模板](../模板/命令与页面接口契约.md) 固定 schema。保存确认是宿主适配，不为了示例给所有软件新增同名领域命令。

## 3. 先证明领域闭环

通过固定测试 ID 生成器建立 `d-1/r-1` 样本。新文档 r0，添加矩形 r1，移动 r2；验证坐标、颜色和对象数。制造旧修订、负宽度和不存在对象，验证拒绝与无部分修改。撤销/重做恢复正确内容。

这些检查通过后再接 UI。测试 ID 只是可重复样本，生产身份仍应唯一。

## 4. 人和程序操作同一内核

工具栏“新建矩形”和鼠标拖动均发上述命令；属性区订阅同一文档。页面公开一个窄入口，例如 `commands / execute / inspect / render / exportProject / acknowledgeSave`，具体签名写入接口文档。

命令回执带 documentId、committedRevision 和结构化 result。`render` 明确等到什么修订，并拒绝已切走的文档请求。程序新增对象后画布实际绘制，选中与属性区对应同一对象。

接 MCP 时从同一注册表生成工具定义，不实现第二套 `shape.move`。平台可拦截官方工具并转给页面；无页面时才在受限原生/无头实例执行并保存交接。

## 5. 确认实时链

先零模型经真实工具做如下序列：

```json
[
  {"id":"shape.add","params":{"documentId":"d-1","kind":"rect","x":40,"y":50,"width":120,"height":80,"fill":"#2563eb","expectedRevision":0}},
  {"id":"shape.move","params":{"documentId":"d-1","nodeId":"r-1","x":100,"y":80,"expectedRevision":1}}
]
```

此序列是串行演练，不宣称原子 batch；实际执行用第一条返回的真实 nodeId。独立读页面应得 r2/(100,80)，截图应出现蓝矩形。再由用户拖到 (140,90)，得到 r3；Agent inspect 得到 r3，再 style 红色得到 r4。读取内容与当前画面，不能只看调用返回。

## 6. 工程和导出

示例保存快照的有效 JSON：

```json
{"version":1,"id":"d-1","title":"课堂示例","width":800,"height":600,"revision":4,"shapes":[{"id":"r-1","kind":"rect","x":140,"y":90,"width":120,"height":80,"fill":"#ef4444"}]}
```

codec 先解析和校验再替换当前工程；导出 SVG/PNG 使用同一领域几何，输出 800×600，不含选择框。导入、主工程、另存与导出分别维护身份。

宿主保存记录快照 r4、目标路径和打开/上次确认摘要，核外改后原子写入，实际成功才确认 r4。若保存期间发生 r5 编辑，确认 r4 后页面仍 dirty。空间满或失败保留修改，另存失败不提前换路径。

## 7. 撤销和重开

保存后销毁页面，从真实 `.craftdemo` 新建页面加载，检查红色、(140,90)、120×80 和标题；再移动到 (160,100)，保存并重新读文件。撤销历史是否跨重开保留由产品范围决定，不能把内存历史当必须已持久化。

导出由独立读取核 SVG 几何/颜色和 PNG 尺寸及矩形区域。测试不能自己写预期 JSON 到主工程来替代保存。

## 8. 接入 IntegrateCraft

复用静态托管、软件目录、官方 MCP、PageChannel、协调器和安全文件 I/O。仅为本款填页面命令与文件差异。定义 `.craftdemo` 自动认领范围，不抢占其他软件普通 SVG；保存落本人空间、只读入口拒写。

使用现有 dsh 主 Agent，模型链不进入示例内核。经授权最后做真实自然语言任务，允许查询参数和同轮自纠；费用与停止按当前卡，不借本教程授权发请求。

## 9. 关键异常和定位

| 异常 | 应有结果 | 首查位置 |
|---|---|---|
| 旧修订移动 | 拒绝，无几何改变 | 命令前置检查 |
| 工具成功画面旧 | 判链路未通过 | 文档身份、订阅和渲染修订 |
| 保存期间再编辑 | r4 被保存，r5 仍 dirty | 快照与确认匹配 |
| 同路径外改 | 拒覆盖，可另存/重载 | 文件基线和真实 I/O |
| 页面关闭后迟到 | 不修改新页面 | 实例生命周期 |
| 空间满 | 不报已保存，内容仍可恢复 | 存储错误传播 |

## 10. 可交付的第一版

交付完整源码、锁定构建、页面与工具契约、真实启动/验证命令、上述内容与画面证据、保存重开和限制。用 [新项目骨架](../模板/新项目文档骨架.md) 让下一个 AI 能在空上下文继续开发。

完成这一版证明通用闭环掌握，再将矩形内核换成实际领域的文档、几何、时间线或数据模型，并按对应专题补算法与格式。不能把完成示例当成复杂领域能力已经完成。
