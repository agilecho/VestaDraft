## 工程检查

本地和 GitHub workflow 均从仓库根运行 `cargo xtask ci`。命令逐项报告 `PASS`、`FAILED` 或 `BLOCKED`。完整关口任一项失败时退出 1，仅有阻塞时退出 2。先备齐锁定离线输入，Cargo jobs 固定为 2。

| 命令 | 当前实际范围 |
|---|---|
| `cargo xtask layers` | 从 Cargo 工作区声明读取所有平台的本地依赖，区分正常、构建和测试边，检查直接与传递依赖。codecs 对 commands 的测试边有单列规则。 |
| `cargo xtask contracts-check` | 将当前工作区的 Git 已跟踪输入复制到临时目录，复用完整 Node 合同测试和 Source7 检查。保护两份锁、合同与生成物，逐字节比对当前 Git 提交和临时生成前后内容。 |
| `cargo xtask ci --independent` | 分层、合同、锁定 TypeScript、xtask 格式与 Clippy、绑定库 Clippy、绑定库两项具名 Rust 测试及 binding-only WASM 类型检查。 |
| `cargo xtask wasm` | 必需范围为绑定、模型、命令三库，使用 `wasm32-unknown-unknown` 与 `--no-default-features`。当前可跑绑定库，模型和命令因 C8 准入待定而报告阻塞。 |
| `cargo xtask ci` | 加入工作区格式检查，报告 C8 相关宏、模型、命令、格式库、CLI 的 Clippy 和测试准入，以及共享内核 WASM 准入。 |
