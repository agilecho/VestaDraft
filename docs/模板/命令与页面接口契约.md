# 命令与页面接口契约模板

新软件在实现前填契约；已有软件记录真实接口并保留 schema。下列字段是通用设计检查项，不是强制覆盖所有原生协议。

## 命令记录

| 字段 | 必须说明 |
|---|---|
| ID 与用途 | 稳定名称及用户结果 |
| 输入 schema | 类型、必填、默认、单位、范围、未知字段处理 |
| 目标身份 | 工程/文档/对象、修订与选择规则 |
| 前置条件 | 页面/资源/权限和合法状态 |
| 副作用 | 内存、文件、网络、进程、设备和费用 |
| 执行结果 | 实际提交范围、修订、资源与分页 |
| 错误 | 稳定错误码、结构化详情和恢复动作 |
| batch/重试 | 原子还是部分执行、幂等与重试条件 |
| 取消/进度 | 可取消边界、事件和超时后的实际状态 |

## 示例类型，仅供新项目设计

```typescript
type CommandRequest = {
  requestId: string;
  documentId: string;
  expectedRevision?: number;
  command: string;
  params: unknown; // 注册表按 command 校验具体 schema
};
type CommandReply =
  | { ok: true; requestId: string; documentId: string;
      committedRevision: number; result: unknown }
  | { ok: false; requestId: string;
      error: { code: string; message: string; details?: unknown } };
```

具体业务 schema 不能始终停在 unknown。`document.new` 等创建命令需要自己的输入/返回，不能强塞一个尚不存在的 documentId。示例实战的扁平 params 可由注册表映射，实际项目选择一种正式线协议并固定。

## 页面生命周期

列出创建、加载、就绪、忙、失败、关闭状态；查询命令、执行、读取状态、渲染、打开、导出、保存确认分别说明输入输出和完成时刻。

回执匹配请求与页面实例；切稿、重载、取消、旧结果和重复请求的处理明确。渲染的目标修订、实际就绪和截图范围必须可查。

## 文件与确认

列快照身份、真实保存目标、字节/资源、写入基线、成功确认和失败反馈。多文件说明提交范围。保存快照后的编辑、另存失败和迟到确认各给一个具体例子。

## 契约验证

至少给正常调用、错误字段、无对象、旧修订、取消、batch 中途失败和文件写入失败的结构化结果。现有软件应以真实调用捕获为依据；新协议示例写明未实现，不把设计 JSON 当运行证据。
