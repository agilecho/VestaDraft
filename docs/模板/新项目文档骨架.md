# 新项目文档骨架

用于让人和 AI 在没有旧聊天的情况下启动、实现与接续新软件。按目标仓库现有规范调整，不覆盖已有权威结构。本模板在本轮只作为文档，不创建新软件仓库。

## 建议资料与职责

| 文件 | 内容 | 更新时机 |
|---|---|---|
| `README.md` | 用户目标、范围、快速启动和真实状态入口 | 入口/范围变化 |
| `AGENTS.md` | 权威顺序、当前上下文、允许修改范围、协作与验证 | 工作规则变化 |
| `docs/PRODUCT.md` | 用户链、领域与格式范围、反例和不做项 | 业务确认后 |
| `docs/ARCHITECTURE.md` | 状态、模块、命令、页面、文件和执行边界 | 接缝变化 |
| `docs/INTERFACES.md` | 真 schema、生命周期、错误与保存协议 | 接口变化 |
| `docs/BUILDING.md` | 锁版本、精确命令、目标、产物与依赖 | 构建输入变化 |
| `docs/TESTING.md` | 样本、独立预期、运行命令与通过条件 | 验证方式变化 |
| `docs/STATUS.md` | 已证明、部分、未知和当前阻塞 | 实际行为变化 |
| `docs/DECISIONS.md` | 已确认决定、依据、适用边界及替代旧口径 | 用户/维护者裁定后 |
| 当前工作说明 | 基线、范围、完整切片、前置、失败处理与证据 | 每项可验交付 |

文件可以合并以适应小项目，职责不重复。不要为文档数量而建空文件；关键信息必须有唯一维护位置。

## AGENTS 需要使新会话知道

项目是什么、哪些目录有领域状态、已有改动归谁、哪里读真实接口、如何构建和验证、什么工作已授权、哪些操作需要单独授权。工具名称用项目真实值，不写不存在的脚本。

规定每次开始核目录/分支/改动，读当前说明；修改后验证新增及受影响行为；结果失败如实保留；退出前更新状态与交接。是否使用并行 Agent、提交推送及权限以该项目规则和用户授权为准。

## 状态条目模板

```text
能力：用户可以完成什么
范围：输入、格式、平台与限制
实现：源码/产物/运行版本
验证：实际命令、环境、内容断言和证据
未验证：还缺什么，下一次怎样核实
下一项：一个可独立交付的用户结果与前置
```

不要以“完成 80%”替代具体能力，也不要把未运行改写成理论上通过。进展证据不覆盖原件。

## 交接材料

写当前目标、最近真实结果、已接受成果、失败最小复现、未完成项、精确环境恢复和继续命令。正在运行的任务、预算、次数及停止条件原样继承，不能因换会话重新开始。

文档启动后，以一条完整用户链实施并回写真实接口；这个骨架本身不证明软件已实现或其他 AI 已验证掌握。
