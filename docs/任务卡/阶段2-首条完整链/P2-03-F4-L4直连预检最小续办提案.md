## 给执行者看的

### 1. 保持同一监听端覆盖整个对照

原脚本的 `endpoint()` 仅调用一次 `accept()`，这次应答已被沙箱外对照用掉。原客户端又在同一异常块内执行连接和读取，因此后续超时无法归因。[F3/L3 探针源码](/Users/agilecho/code/VestaDraft/output/vesta-p2-03/20261121-framework-f3-l3/attempt.py:54)

获准后在新执行目录修订探针。将一次性应答改为带停止信号与短接受超时的循环。监听端完成 `bind/listen` 后通知就绪，由同一监听线程覆盖沙箱外对照和沙箱内探针。每次接受连接都记录事件、发送预期字节，再关闭该连接。监听线程单独记录意外退出或发送错误，供主线程判断。可在探针结束后再做一次沙箱外对照，确认该端点在整个窗口可用。最后在清场阶段停止循环、关闭监听 socket 并等待线程退出。

非环回对照使用本机拥有的非环回 IPv4 地址和与允许代理相同的端口号 17732，验证的是地址限制。指定环回端口可连、另一环回端口被拒的检查用于验证端口限制。探针仅使用本机自建端点。新的执行组重新核对脚本和 SBPL 的 SHA，并按修订后的探针取得本机证据。G15 与 F3/L3 的原日志和执行账继续封存。

### 2. 分别记录 connect 和 recv

每条探针给定唯一标识，记录规则 SHA、目标地址与端口、沙箱内外、操作阶段、单调时间、结果与原始 errno。监听端记录对应的接受和发送事件，便于复核对照的完整过程。

| 操作或结果 | 判定 |
|---|---|
| `connect()` 返回成功 | 立即写入 `connect=ok`。对禁止路径，立刻判为隔离失败并关闭连接，记录 `recv=未执行` |
| `connect()` 返回 `EPERM` 或 `EACCES` | 在同地址端口的沙箱外对照成功且监听端健康时，算明确拒绝。记录 `recv=未执行` |
| 其他连接错误或超时 | 默认未证拒绝。只有可独立核实的系统沙箱拒绝记录能补证，须匹配本次进程、目标和连接操作。端口未监听、连接被拒绝、缺路由或笼统超时均不足 |
| 允许路径的 `connect()` 成功 | 再以独立处理块执行有界 `recv()`，记录收到的字节和结果。收到预期内容才算允许路径通过。读取超时或 EOF 单独记录 |

直接准入门槛为沙箱外非环回应答成功、沙箱内明确拒绝同一目标，以及指定代理环回端口正常、另一环回端口明确被拒。若沙箱内非环回连接成立，即使读取失败也要停止。规则加载成功和环回端口测试通过只证明各自检查的结果。
