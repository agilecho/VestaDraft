# P2-03 C8 VICS 与 NVIS 最小采集提案

**提案待批。本轮仅静态核对。** 目标是在原件与锁定程序上获得可独立复算的旧 VICS 读入状态，以及 NVIS 生成对象与旗标的逐项对应。本提案复用原 VICS 二进制、两件旧输入、Anatase 原件及已定位的 arm64 代码位置。 [原 C8 提案](P2-03-C8全类型与资源闭合最小续办提案.md) · [上轮二进制及归档证据](/Users/agilecho/code/VestaDraft/output/vesta-p2-03/20261121-c8-archived-producers/archive-check.json)

## 给你看的

拟最多 **4 次程序启动，合计 900 秒**。在已有 Windows 目标上采一组原版 VICS 状态，再用已有锁定版 macOS VESTA 分别读取两件旧文件，最后采 Anatase 生成面及实际标签。接受依据是同次读取前后实际状态、导出字节和逐对象对应。上轮实证的 YBa 对象数量与输出可以交叉核对，本轮不再消耗历史回执。

1. **静态准备。** 从已封存证据取 Windows PE、macOS 主/库、两件旧 VICS、Anatase 及配置文件。另立 RUN，保留原件和证据摘要。使用上轮核验的 `readdata`、`BondSpec`、`Scene::UpdateBondsProperties`、`get_spin_from_file`、`HKLPlane::PrintIndex` 作 arm64 观察入口，按实际映射换算地址。Windows 按自己的二进制查明字段。归档 599 条指令对应结果用于前置地址校验。 [原二进制和观察地址](/Users/agilecho/code/VestaDraft/output/vesta-p2-03/20261121-c8-archived-producers/archive-check.json)
2. **每次采集。** 冻结开始的文件清单和 SHA，记录真实 argv、代码载入地址、配置、观察点命中顺序、对象指针与对象语义身份、阶段时间、退出与清场。每个 raw 范围带模块、地址、宽度、顺序和 SHA，编辑后的对象映射以相、定义和生成实例归属证明。同次保存保留未改写的主件、日志及 manifest。旧 VESTA 可能返回 255，分别记录终止原因与实际写出。
3. **独立判据。** 独立解码文件和原始字节，核相同输入、读前后的同一实际 owner、同一修订的有效标志及归属，核原文件保持完整。明确区分 Win32 原程序、锁定版 legacy 兼容入口和 NVIS 动态证据。工程 R80 箱体、原有 YBa 已打印数量和静态函数部位各保留原资格。非周期多面体若缺有资格的生产输入及映射，在本计划结束仍单列。只有来源与逐项语义均对齐的结果进入原 C8 候选矩阵。
4. **停止条件。** 任一环境、二进制、符号或可捕获性无法确认，相关目标不启动。启动后失败、超时、异常写入及清场均计本次。捕获器被签名或调试权限拒绝时保留原诊断，结束相应步骤。提出的同组重试上限为 0，空余额不换更多启动。作业串行、隔离可写根、禁网，原件及共享偏好只读。按原卡保守资源上限约束或取各环境可提供的更严上限。
5. **交付。** 每个目标保存 `argv.json`、`input-manifest.json`、`trace.jsonl`、原始状态块、输出字节、独立核对表及结束回执。可由用户手动交 dsh 独审。V1–V3 为拟单列的证据次数，若获准同样纳入原全卡和续办时间账。C8≤1800 秒、G29/G30 各≤600 秒和各组启动条件沿用。
